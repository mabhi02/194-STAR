Introduction to Databases and SQL

What is a Database?

A database is an organized collection of structured data stored electronically on a computer system. Databases are designed to efficiently store, manage, and retrieve information.

Key Database Concepts:

  • Database Management System (DBMS): Software that manages databases, like MySQL, PostgreSQL, Oracle, or Microsoft SQL Server.
  • Relational Database: Organizes data into tables with relationships between them.
  • Table: A collection of related data organized in rows and columns (similar to a spreadsheet).
  • Row: Also called a record or tuple, represents a single entity in a table.
  • Column: Also called a field or attribute, represents a specific piece of data all records have.
  • Primary Key: A unique identifier for each row in a table.
  • Foreign Key: A field in one table that connects to the primary key in another table.

What is SQL?

SQL (Structured Query Language) is a standardized programming language specifically designed for managing and manipulating relational databases. It allows you to create database structures, insert data, update information, delete records, and retrieve specific data based on various criteria.

SQL Can Be Used For:

  • Creating and modifying database structures
  • Adding, updating, and removing data
  • Retrieving data with specific criteria
  • Performing calculations and aggregations on data
  • Combining data from multiple tables
  • Controlling access to data

Note: While SQL is standardized, different database systems (like MySQL, PostgreSQL, Oracle, etc.) may have slight variations in syntax. This tutorial focuses on standard SQL that works across most systems.

Part 1: Basic SQL Queries

The SELECT Statement

The SELECT statement is the most commonly used command in SQL. It allows you to retrieve data from one or more tables in a database.

Basic SELECT Syntax:

SELECT column1, column2, ...
FROM table_name;

This retrieves specific columns from a table.

To select all columns:

SELECT *
FROM table_name;

The asterisk (*) is a wildcard that represents all columns.

Example 1: Selecting specific columns

SELECT title, author, price
FROM books;

This query retrieves only the title, author, and price columns from the books table.

Result:

title author price
SQL Fundamentals Jane Smith 29.99
Data Analysis John Doe 45.99
Database Design Alice Johnson 52.50
... ... ...

Example 2: Selecting all columns

SELECT *
FROM books;

This query retrieves all columns from the books table.

Best Practice: While SELECT * is convenient for exploration, in production code it's better to specify exactly which columns you need. This improves performance and reduces network traffic.

Part 2: Filtering Data with WHERE

The WHERE Clause

The WHERE clause allows you to filter records based on specific conditions, returning only the rows that satisfy those conditions.

WHERE Syntax:

SELECT column1, column2, ...
FROM table_name
WHERE condition;

Common Operators Used in WHERE Clauses:

Operator Description Example
= Equal to genre = 'Fiction'
> Greater than price > 40
< Less than price < 30
>= Greater than or equal to publication_year >= 2020
<= Less than or equal to page_count <= 400
!= Not equal to genre != 'Fiction'
BETWEEN Between a range (inclusive) price BETWEEN 20 AND 50
LIKE Pattern matching with wildcards title LIKE 'SQL%'
IN Matches any value in a list genre IN ('Fiction', 'History')
IS NULL Is a NULL value publisher IS NULL

Example 1: Simple comparison

SELECT title, price, genre
FROM books
WHERE price > 40;

This query finds all books with a price greater than $40.

Result:

title price genre
Data Analysis 45.99 Education
Database Design 52.50 Education
Python for Beginners 49.99 Education
Advanced SQL 59.99 Education
Web Development 47.50 Education

Example 2: Using BETWEEN

SELECT title, price, publication_year
FROM books
WHERE publication_year BETWEEN 2020 AND 2021;

This query finds all books published in 2020 or 2021.

Example 3: Using IN

SELECT title, author, genre
FROM books
WHERE genre IN ('Fiction', 'History');

This query finds all books in either the Fiction or History genres.

Example 4: Using LIKE

SELECT title, author
FROM books
WHERE title LIKE 'SQL%';

This query finds all books with titles that start with "SQL". The % is a wildcard that matches any number of characters.

LIKE Pattern Wildcards:

  • % - Matches any sequence of characters (including zero characters)
  • _ - Matches exactly one character

Examples:

  • LIKE 'SQL%' - Starts with "SQL"
  • LIKE '%SQL' - Ends with "SQL"
  • LIKE '%SQL%' - Contains "SQL" anywhere
  • LIKE '_ython' - Second letter is 'y', followed by "thon" (matches "Python")

Logical Operators

Logical operators allow you to combine multiple conditions in a WHERE clause.

Logical Operators:

  • AND - Returns TRUE if both conditions are TRUE
  • OR - Returns TRUE if either condition is TRUE
  • NOT - Returns TRUE if the condition is FALSE

Example 1: Using AND

SELECT title, genre, price
FROM books
WHERE genre = 'Education' AND price > 45;

This query finds all Education books with a price greater than $45.

Example 2: Using OR

SELECT title, author, genre
FROM books
WHERE genre = 'Fiction' OR genre = 'History';

This query finds all books in either the Fiction or History genres.

Example 3: Using NOT

SELECT title, genre, price
FROM books
WHERE NOT genre = 'Education';

This query finds all books that are not in the Education genre.

Example 4: Combining AND and OR

SELECT title, author, price, genre
FROM books
WHERE (genre = 'Education' OR genre = 'History')
AND price < 40;

This query finds all Education or History books with a price less than $40.

Note: Parentheses are used to establish precedence in complex conditions.

Part 3: Sorting Results with ORDER BY

The ORDER BY Clause

The ORDER BY clause sorts the result set based on specified columns, either in ascending (ASC) or descending (DESC) order.

ORDER BY Syntax:

SELECT column1, column2, ...
FROM table_name
ORDER BY column1 [ASC|DESC], column2 [ASC|DESC], ...;

By default, ORDER BY sorts in ascending order (ASC). You need to specify DESC for descending order.

Example 1: Basic sorting

SELECT title, price
FROM books
ORDER BY price DESC;

This query retrieves all books sorted by price from highest to lowest.

Result:

title price
Advanced SQL 59.99
Database Design 52.50
Python for Beginners 49.99
... ...

Example 2: Multiple columns sorting

SELECT title, author, publication_year
FROM books
ORDER BY publication_year ASC, title ASC;

This query sorts books first by publication year (oldest to newest), and then alphabetically by title for books published in the same year.

Example 3: Sorting by column position

SELECT title, price, publication_year
FROM books
ORDER BY 2 DESC;

This query sorts by the second column in the SELECT list (price) in descending order. However, using column positions is not recommended for production code as it makes queries harder to maintain.

Part 4: Joining Tables

Introduction to JOINs

In relational databases, data is often spread across multiple tables to minimize redundancy and improve data integrity. JOINs allow you to combine data from multiple tables based on related columns.

The Need for JOINs:

Consider our database: book information is in the books table, while order information is in the book_orders table. If we want to see which books were ordered and their details, we need to join these tables.

The book_id column in book_orders references the id column in books, creating a relationship between the tables.

Types of JOINs

SQL supports several types of JOINs, each with specific behaviors:

Main JOIN Types:

  • INNER JOIN: Returns only matching rows from both tables
  • LEFT JOIN (or LEFT OUTER JOIN): Returns all rows from the left table and matching rows from the right table
  • RIGHT JOIN (or RIGHT OUTER JOIN): Returns all rows from the right table and matching rows from the left table
  • FULL JOIN (or FULL OUTER JOIN): Returns all rows when there's a match in either table

INNER JOIN

The INNER JOIN returns only the rows where there's a match in both tables based on the specified join condition.

INNER JOIN Syntax:

SELECT columns
FROM table1
INNER JOIN table2 ON table1.column = table2.column;

Example: Finding book details for all orders

SELECT bo.id AS order_id, b.title, bo.order_date, bo.quantity
FROM book_orders bo
INNER JOIN books b ON bo.book_id = b.id;

This query joins the book_orders and books tables to show which books were ordered, including the order date and quantity.

Result:

order_id title order_date quantity
1 SQL Fundamentals 2023-01-15 2
2 Database Design 2023-01-16 1
3 Data Analysis 2023-01-20 1
... ... ... ...

How this works:

  1. For each row in book_orders, the database finds matching rows in books where book_orders.book_id = books.id
  2. Only rows that have matches in both tables are included in the result
  3. The result combines data from both tables

Note: The word "INNER" is optional. Simply writing "JOIN" defaults to an INNER JOIN.

LEFT JOIN

The LEFT JOIN returns all rows from the left table and matching rows from the right table. If there's no match, NULL values are returned for columns from the right table.

LEFT JOIN Syntax:

SELECT columns
FROM table1
LEFT JOIN table2 ON table1.column = table2.column;

Example: Finding all books and their orders (if any)

SELECT b.title, bo.order_date, bo.quantity
FROM books b
LEFT JOIN book_orders bo ON b.id = bo.book_id;

This query retrieves all books from the books table and any matching orders from the book_orders table. Books without orders will have NULL values for order_date and quantity.

Partial result (showing books with and without orders):

title order_date quantity

... ... ...

How this works:

  1. All rows from the left table (books) are included
  2. For each book, matching orders are included (if any exist)
  3. Books without any orders still appear, but with NULL values for the order columns

Table Aliases

Table aliases provide shorthand names for tables in a query, making it easier to write and read, especially for complex queries with multiple joins.

Table Alias Syntax:

SELECT columns
FROM table_name AS alias_name;

As with column aliases, the AS keyword is optional.

Example: Using table aliases

SELECT b.title, a.name AS author_name
FROM books b
JOIN authors a ON b.author_id = a.id;

In this example (assuming an authors table), "b" is an alias for the books table and "a" is an alias for the authors table.

Best Practice: Use meaningful aliases that reflect the table name (like "b" for books, "bo" for book_orders). This makes your queries more readable and maintainable.

Joining with WHERE Conditions

You can combine JOINs with WHERE clauses to filter the joined data.

Example: Find orders for books with a price greater than $40

SELECT b.title, bo.order_date, bo.quantity, b.price
FROM book_orders bo
JOIN books b ON bo.book_id = b.id
WHERE b.price > 40;

This query joins the tables and then filters to show only orders for books priced above $40.

Part 5: Aggregate Functions and GROUP BY

Aggregate Functions

Aggregate functions perform calculations on a set of values and return a single value. They're used to summarize data.

Common Aggregate Functions:

Function Description Example
COUNT() Counts the number of rows COUNT(*) or COUNT(column)
SUM() Calculates the sum of values SUM(price)
AVG() Calculates the average of values AVG(price)
MIN() Finds the minimum value MIN(price)
MAX() Finds the maximum value MAX(price)

Example 1: Counting records

SELECT COUNT(*) AS total_books
FROM books;

This query counts the total number of books in the database.

Result:

total_books
10

Example 2: Multiple aggregates

SELECT 
    COUNT(*) AS book_count,
    AVG(price) AS average_price,
    MIN(price) AS lowest_price,
    MAX(price) AS highest_price,
    SUM(price) AS total_value
FROM books;

This query calculates multiple statistics about book prices in a single query.

Result:

book_count average_price lowest_price highest_price total_value
10 37.39 19.99 59.99 373.89

When using aggregate functions without GROUP BY, they operate on the entire result set, returning a single row.

The GROUP BY Clause

The GROUP BY clause divides the result set into groups based on specified column values, allowing aggregate functions to operate on each group separately.

GROUP BY Syntax:

SELECT column1, aggregate_function(column2)
FROM table_name
GROUP BY column1;

What GROUP BY does:

  1. Groups rows that have the same values in the specified column(s)
  2. Returns one row for each group
  3. Allows aggregate functions to be applied to each group independently

Important Rule: When using GROUP BY, columns in the SELECT clause must either:

  • Be included in the GROUP BY clause, OR
  • Be used within an aggregate function

This is because non-aggregated columns must have a single value per group.

Example 1: Simple GROUP BY

SELECT genre, COUNT(*) AS book_count
FROM books
GROUP BY genre;

This query counts how many books are in each genre.

Result:

genre book_count
Education 5
Fiction 2
History 1
Cooking 1

How this works:

  1. The database groups rows with the same genre value
  2. The COUNT(*) function counts how many rows are in each group
  3. One row is returned for each unique genre

Example 2: GROUP BY with multiple aggregates

SELECT 
    publication_year, 
    COUNT(*) AS book_count,
    AVG(price) AS average_price,
    MIN(price) AS lowest_price,
    MAX(price) AS highest_price
FROM books
GROUP BY publication_year
ORDER BY publication_year;

This query groups books by publication year and calculates various statistics for each year.

Result:

publication_year book_count average_price lowest_price highest_price
2019 2 35.49 24.99 45.99
2020 3 39.16 29.99 47.50
2021 3 41.81 22.95 52.50
2022 2 39.99 19.99 59.99

Example 3: GROUP BY with JOIN

SELECT 
    b.genre, 
    COUNT(bo.id) AS total_orders,
    SUM(bo.quantity) AS books_sold
FROM books b
JOIN book_orders bo ON b.id = bo.book_id
GROUP BY b.genre
ORDER BY books_sold DESC;

This query joins the books and book_orders tables, then groups the results by genre to find which genres have the most orders and total books sold.

Result:

genre total_orders books_sold
Education 8 10
History 2 4
Fiction 3 5
Cooking 1 3

The HAVING Clause

While the WHERE clause filters individual rows before grouping, the HAVING clause filters groups after the GROUP BY has been applied.

HAVING Syntax:

SELECT column1, aggregate_function(column2)
FROM table_name
GROUP BY column1
HAVING condition;

The condition in the HAVING clause typically involves an aggregate function.

Example: Find genres with more than one book

SELECT genre, COUNT(*) AS book_count
FROM books
GROUP BY genre
HAVING COUNT(*) > 1;

This query groups books by genre, but only shows genres that have more than one book.

Result:

genre book_count
Education 5
Fiction 2

WHERE vs. HAVING:

  • WHERE filters rows before they are grouped
  • HAVING filters groups after the GROUP BY is applied

Both can be used in the same query:

SELECT column1, aggregate_function(column2)
FROM table_name
WHERE condition1
GROUP BY column1
HAVING condition2;

Example: Combining WHERE and HAVING

SELECT 
    author, 
    COUNT(*) AS book_count, 
    AVG(price) AS avg_price
FROM books
WHERE publication_year > 2019
GROUP BY author
HAVING COUNT(*) > 1;

This query finds authors who have written multiple books published after 2019.
